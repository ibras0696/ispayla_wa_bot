## Ключевые возможности

- **Green API + long polling** — никаких вебхуков, бот сам регулярно опрашивает Green API и регистрирует нужные уведомления.
- **Интерактивные меню** — главное меню и все подэкраны приходят через `sendInteractiveButtonsReply`: кнопки «Профиль», «Продажа», «Покупка» плюс универсальная «⬅️ В меню».
- **Профиль одним сообщением** — карточка профиля (ID, имя, баланс, регистрация) отправляется сразу с кнопкой возврата.
- **Продажа** — пошаговый мастер (заголовок → описание → цена → марка → модель → год → пробег → VIN → регион → состояние → фото), хранение изображений в `media/uploads`, показ своих объявлений с фото и кнопкой назад.
- **Покупка** — каталог активных объявлений, поиск по названию, избранное, фильтры по цене/году/пробегу/марке/региону/состоянию и сортировка по дате или цене.
- **Галерея объявлений** — при открытии карточки бот отправляет все загруженные изображения (локальные файлы или ссылки из БД автоматически кешируются).
- **Избранное** — открыли карточку → отправили «в избранное» → всегда под рукой список сохранённых объявлений.
- **Whitelists** — переменная `ALLOWED_SENDERS` ограничивает тестирование конкретными чатами.
- **Docker-ready** — Postgres 16 + бот запускаются одной командой, стейт держится в volume, медиа-маунт в контейнер.

## Архитектура и модули

```
app/
├── bot_runner.py      # Точка входа: создаёт GreenAPIBot и запускает .run_forever()
├── bot/
│   ├── handlers/      # business-логика (menu/basic/sell/buy/profile)
│   ├── services/      # guard (whitelist), forms (FSM продаж), state (доступ к БД)
│   ├── ui/            # кнопки + тексты
│   └── runner.py      # регистрация хендлеров, настройка бота
├── database/          # SQLAlchemy модели и CRUD-слой

docs/                  # обзоры, Чек-листы, журнал изменений, samples Green API
media/uploads          # сохранённые фотографии объявлений
```

- **Обработчики** (`app/bot/handlers/**`) делятся по сценариям, каждый принимает `Notification` и возвращает ответы через Green API.
- **Сервисы** (`app/bot/services/state.py`) скрывают асинхронный CRUD за синхронным фасадом `DBRunner`, чтобы хендлеры оставались простыми.
- **UI** (`app/bot/ui`) хранит тексты и кнопки — любой copy update делается централизованно.
- **CRUD** (`app/database/crude`) содержит слой работы с Postgres: объявления, бренды, фото, избранное, модерация, платежи.

## Пользовательские сценарии

### 1. Главное меню
- Триггеры: команда `меню` (или кнопка «⬅️ В меню»).
- Отправляется сообщение с кнопками «Профиль», «Продажа», «Покупка».
- Любой активный мастер продаж сбрасывается автоматически, пользователь получает подтверждение возврата в меню.

### 2. Профиль
- Кнопка «Профиль» или текст `профиль/profile`.
- Ответ приходит интерактивным сообщением: ID, имя, баланс, дата регистрации и сразу кнопка «⬅️ В меню».
- Если по каким-то причинам кнопка не доставлена, можно написать `меню` — обработчик всегда наготове.

### 3. Продажа
- **Разместить объявление** — мастер из 11 шагов:
  1. Заголовок  
  2. Описание  
  3. Цена  
  4. Марка  
  5. Модель  
  6. Год  
  7. Пробег  
  8. VIN  
  9. Регион  
  10. Состояние (целый / после ДТП)  
  11. Фото (до 3 штук, по одному сообщению)

  Команда `отмена`/`стоп`/`меню` завершает мастер и возвращает меню. После успешного сохранения бот сообщает ID объявления и напоминает про кнопку «⬅️ В меню».

- **Мои объявления** — статистика (всего / активные) + последние карточки. Можно написать `объявление 1`, `объявление ID42` или просто номер — бот пришлёт подробности и до трёх фото.
- После каждой выдачи добавляется кнопка «⬅️ В меню», поэтому возврат — один тап.

### 4. Покупка
- **Все объявления** — каталожный лист: страница, сортировка, список с ID. Кнопки навигации: «⬅️ Предыдущая», «➡️ Следующая», «Обновить список» и «⬅️ В меню».
- **Фильтры** — текстовые команды:  
  - `цена 100000-500000`  
  - `год 2015-2020` или `год 2018`  
  - `пробег 0-150000`  
  - `марка Toyota`  
  - `регион Грозный` / `регион любой`  
  - `состояние целый` / `состояние после ДТП`  
  - `сорт цена дешевле`, `сортировка дата`  
  - `сброс` — очистка фильтров  

- **Поиск авто** — после кнопки «Поиск» бот ждёт текст (марка/модель) и выводит до 5 совпадений.
- **Избранное** — после просмотра карточки можно отправить «в избранное». Кнопка «Избранное» выводит список сохранённых объявлений с возможностью открыть карточку по номеру или ID.
- Карточка объявления всегда включает фото-галерею (до 3 снимков для публичного каталога) и напоминание о кнопке возврата.

### 5. Общие команды

| Команда/кнопка | Действие |
| -------------- | -------- |
| `/start`       | Приветствие, подсказка про «меню» и whitelisted поведение |
| `баланс`       | Баланс из таблицы `users` |
| `меню`         | В любое время открывает главное меню и сбрасывает активные мастеры |
| `профиль/продажа/покупка` | Текстовые аналоги кнопок |

## UI/UX принципы

- **Кнопка возврата в каждом сценарии.** После любого действия (профиль, список объявлений, карточка, каталог) бот отправляет «⬅️ В меню».
- **Только осмысленные тексты.** Никаких цифр `0/00`: команды — живые слова (`меню`, `фильтры`, `марка Toyota`). Подсказки закреплены в `app/bot/ui/texts.py`.
- **Единый клиент кнопок.** Все интерактивные ответы отправляются через `WhatsKeyboardClient` (`app/bot/services/keyboard.py`), поэтому UX одинаковый.
- **Фото без ограничений.** Для внутренних объявлений отправляются все снимки, для публичного каталога — до трёх; если файл лежит на внешнем URL, он кешируется в `media/cache`.
- **Падение API ≠ тихая ошибка.** Любой сбой при отправке кнопок логируется и дублируется текстовым сообщением, чтобы пользователь не остался без инструкции.

## Быстрый старт

### 1. Подготовка окружения
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
```

Обязательно заполните `.env`:
```
ID_INSTANCE=xxxxxxxxxx
API_TOKEN=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
POSTGRES_USER=app
POSTGRES_PASSWORD=change_me
POSTGRES_DB=appdb
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
ALLOWED_SENDERS=79323056361,79323056361@c.us
```

### 2. Быстрая установка и запуск
```bash
make install     # venv + зависимости
make bot         # локальный запуск через python -m app.bot_runner
```

### 3. Вариант на Docker/Compose
```bash
docker compose up -d --build
# внутри поднимутся:
# - postgres:16 (порт 5432 наружу)
# - bot (python -m app.bot_runner, конфиг из .env)
```

> Переключатели `make up`, `make down`, `make logs` и др. перечислены ниже.

## Тесты и качество

- `pytest` покрывает вспомогательные функции раздела покупки (фильтры, сохранение состояния, сортировки).
- `ruff` следит за стилем (`E`, `F`, `W`, `B`, `I`), целевой Python — 3.12.
- В `docs/CHECKLIST.md` ведётся чек-лист готовности, а в `docs/journal.md` — журнал изменений по датам.
- Фильтры покупки сериализуются в `state_filters.json`, чтобы переживать рестарты; данные объявлений и пользователей всегда в Postgres.

## Работа с состояниями и данными

- **База данных** — Postgres 16, async SQLAlchemy + отдельный `DBRunner`, чтобы не плодить event loop в обработчиках.
- **Фото** — файлы складываются в `media/uploads` (маунтится в контейнер `bot`). Пути записываются в таблицу `ad_images`.
- **Whitelist** — `ALLOWED_SENDERS` принимает список номеров (с/без `@c.us`). Если переменная пуста, бот отвечает всем.
- **Состояния продажи** — держатся в памяти процесса (`SellFormManager`), но любые отмены/возвраты обрабатываются корректно: достаточно написать «отмена»/«меню» или нажать кнопку «⬅️ В меню».
- **Каталог** — in-memory кэш `_LAST_CATALOG`, `_LAST_DETAILS`, `_LAST_VIEWED` помогает открывать карточки по номеру без повторных запросов.

## FAQ и полезные заметки

**Что делать, если бот молчит?**  
1. Проверьте `.env`: `ID_INSTANCE`, `API_TOKEN`, а также `ALLOWED_SENDERS`.  
2. Посмотрите логи контейнера: `docker compose logs -f bot`.  
3. Убедитесь, что уведомления Green API активированы (библиотека делает это автоматически при старте, но токен должен быть валиден).

**Как добавить новую функцию?**  
1. Создайте хендлер или расширьте существующий.  
2. Зарегистрируйте его в `app/bot/runner.py` через `bot.router`.  
3. Тексты/кнопки выносите в `app/bot/ui/**`.  
4. При работе с БД добавьте метод в CRUD (`app/database/crude`) и фасад в `services/state.py`.

**Можно ли использовать без Docker?**  
Да. Достаточно локального Postgres (либо `docker run postgres`, либо любой другой инстанс) и запуска `make bot`. Главное — правильно заполнить переменные окружения.

**Сколько кнопок можно отправить?**  
Green API теперь поддерживает более трёх кнопок в `sendInteractiveButtonsReply`, поэтому меню «Покупка» и навигация содержат дополнительную кнопку «⬅️ В меню». Если будете добавлять ещё, тестируйте в тестовом инстансе — лимиты могут меняться.
